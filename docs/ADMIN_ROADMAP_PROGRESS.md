# 관리자 센터 단계별 개선 이력

이 문서는 관리자 센터 개선 1~4단계를 각각 독립된 Git 체크포인트로 저장하고, 다음 단계 진행 전 이전 단계와 비교하기 위한 기록이다.

## 진행 원칙

- 각 번호는 별도 완료 기준을 통과한 뒤 체크포인트 커밋으로 저장한다.
- 다음 번호는 직전 체크포인트를 기준으로 진행한다.
- 기존 직원용 화면·기능과 개인 배송기록·개인 계정 설정은 해당 단계의 명시적 범위가 아니면 수정하지 않는다.
- 현재 구조인 업체 대표 계정 1개 관리 권한을 유지한다. 복수 관리자, 대표/일반 관리자 구분, 관리자 추가 구매는 이번 1~4단계에서 구현하지 않는다.
- Supabase 운영 DB에는 사용자가 별도로 승인하기 전까지 마이그레이션을 적용하지 않는다.

## 단계별 범위와 상태

| 번호 | 작업 | 완료 기준 | 상태 |
|---|---|---|---|
| 1 | 관리자 데이터 백업·복구 | 자동 변경 이력, 수동 백업, 이력 조회, 복구 전 비교, 복구 직전 백업, 권한 및 빌드 검증 | 구현 후 검증 대기 |
| 2 | 주간 근무표 작성 편의 | 템플릿 저장/불러오기, 지난주 복사, 임시 미리보기, 확정 이력 및 복구, 기존 모바일·웹 동기화 유지 | 대기 |
| 3 | 휴무 요청·승인 | 휴무 교환과 추가 휴무 요청, 승인/거절, 직원 화면 반영 및 이력 확인 | 대기 |
| 4 | 부족량 분석·자동 배치 | 노선별 부족량 계산, 백업 배치, 격주 검증, 초과/부족 검증, 미리보기·확정·변경 이력 | 대기 |

## 1단계 구현 기록

- 대상 데이터: 회사 공용 지역·팀·직원·노선만 포함.
- 제외 데이터: 직원 개인 배송기록, 개인 설정, 로그인/인증 정보.
- 자동 백업: 공용 관리자 데이터가 변경되면 변경 직전 버전을 저장.
- 수동 백업: 관리자가 현재 시점을 직접 저장 가능.
- 보관 정책: 업체별 최근 50개 또는 최근 90일 이내의 백업을 유지.
- 복구: 선택 백업의 분류별 항목 수를 현재 데이터와 비교한 뒤 복구 실행.
- 복구 안전장치: 복구 직전 데이터를 pre_restore 백업으로 보관.
- 보안: 백업 테이블 직접 Data API 접근 차단, 사용자 인증 및 업체 대표 권한 확인 RPC만 허용.
- 마이그레이션: supabase/migrations/20261119194500_admin_data_backup_restore.sql
- 코드 파일: src/admin/AdminDataBackup.jsx, src/admin/Main.jsx, src/services/teamService.js
- 검증 상태: GitHub Actions 결과 반영 예정.
- 체크포인트 기준 커밋: f326bef12489cb0366ca391e01ea00b00818ccbe (화면·서비스·마이그레이션 코드 반영 완료 시점)

## 단계 간 비교 방법

각 단계의 체크포인트 SHA를 이 문서에 기록한다. 다음 단계 작업 전후에는 git diff <직전 체크포인트 SHA>..<이번 체크포인트 SHA>로 변경 범위를 비교한다. PR은 검토·검증이 끝나기 전까지 병합하지 않는다.
