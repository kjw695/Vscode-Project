# 관리자 센터 단계별 개선 이력

이 문서는 관리자 센터 개선 1~4단계를 독립된 Git 기준점으로 저장하고, 나중에 단계 간 변경점을 비교하기 위한 작업 기록이다.

## 진행 원칙

- 각 번호는 개별 체크포인트 브랜치와 기준 커밋 SHA로 저장한다.
- 다음 번호 작업은 직전 번호의 체크포인트를 기준으로 이어간다.
- 기존 직원용 화면·기능은 유지한다. 해당 단계 범위에 없는 직원용 동작은 변경하지 않는다.
- 현재 업체 대표 계정 1개 관리 구조를 유지한다. 복수 관리자, 대표/일반 관리자 구분, 관리자 추가 구매는 구현하지 않는다.
- 직원 개인 배송기록, 개인 계정 설정, 로그인 정보는 회사 관리자 데이터 백업 범위에 넣지 않는다.
- 운영 DB 변경은 적용 전 백업·사전 점검을 하고, 적용 후 실제 DB와 migration history를 확인한다.
- 단계 범위를 벗어난 팀관리·직원 프로필·노선관리 기능은 수정하지 않는다.

## 운영 DB 마이그레이션 완료

운영 프로젝트 `delivery-app` (`rrjoilqlsyilqqtzybps`)에 총 17개 migration이 applied로 기록되어 있다. 기존 공유 관리자 데이터 4개 migration은 이미 적용된 상태를 확인했고 재실행하지 않았다. 신규 확정 근무표 보호 migration은 원격 기록 버전 `20261120122049`, 템플릿 저장 기능 제거 migration은 `20261120125422`로 적용했다. 저장소 파일명도 원격 버전과 일치시켰다.

적용 후 검증:
- 주간 근무표 2건, 기준 이력 2건 유지
- 감사 컬럼 5개 생성 및 기존 기준 이력의 after snapshot/result version 채움
- 확정 일정 보호 트리거 설치
- 신규 RPC 3개 authenticated만 실행 가능, anon 실행 불가
- 기존 직접 테이블 권한 없음 및 RLS 유지
- 사유 없는 확정 근무표 수정 시도 거부 확인(테스트 변경은 롤백, 운영 데이터 변화 없음)

상세한 원격 migration 버전과 검증 쿼리 결과는 `docs/SUPABASE_PRODUCTION_MIGRATION_RUNBOOK.md`를 참조한다.

## 근무표 편의도구 UI 및 템플릿 DB 제거 (2026-11-20)

자동 휴무 생성이 핵심 목표이므로, 사용하지 않는 편의 기능을 기존 관리자 주간 근무표 화면에서 제거했다.

- 제거: 팀별 근무표 템플릿 저장/불러오기/삭제
- 제거: 지난주 근무표 복사
- 제거: 임시 근무표 미리보기
- 제거: 화면의 과거 근무표 이력 조회·복구 패널
- 정리: 위 UI 전용 React 컴포넌트와 서비스 호출부 삭제
- DB: 템플릿 전용 테이블과 RPC 4개 제거 (적용 전 템플릿 0건)
- 유지: 주간 근무표 생성·수정·임시 저장·확정, 확정 변경 사유 기록, DB 감사 이력 저장, 직원별 변경 안내
- 자동 휴무 생성 및 고정 휴무 기능은 이번 UI 삭제 작업에서 수정하지 않았다.

템플릿 데이터가 0건임을 확인한 뒤 템플릿 테이블과 전용 RPC만 제거했다. 확정 일정 변경 감사 이력 테이블은 계속 유지한다.

## 현재 남은 실사용 확인

- GitHub Actions APK를 추출해 Android Debug APK를 확보했다. 아직 실제 기기에서 설치·로그인·업무 흐름을 실행한 것은 아니다.
- 대표 계정에서 확정 근무표 수정·확정 해제 시 사유 필수 동작 확인
- 직원 계정에서 본인 일정 변경 안내 표시 확인
- 직원의 추가휴무 요청 승인 및 휴무 교환 승인 동작 확인
- 안내는 앱의 직원용 달력 화면을 열고 동기화할 때 나타나는 인앱 안내다. 네이티브 푸시(FCM)는 구현하지 않았다.
- PR 병합은 `feature/account-data-isolation`에 반영했다. `security-audit` 또는 배포 브랜치로의 승격과 앱 스토어 배포는 별도 단계다.

## 변경 범위

- 백업 대상: 회사 공용 지역·팀·직원·노선.
- 근무표 이력 대상: 팀별 주간 schedule, 직원 상세, 경고, 임시/확정 상태.
- 휴무 이력 대상: 직원 간 휴무 교환 및 추가 휴무 요청의 처리 결과.
- 개인 배송기록 및 개인 설정: 제외.
- 관리자 권한: 현행 대표 계정 1개 구조 유지.
