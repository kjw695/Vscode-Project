# 관리자 센터 단계별 개선 이력

이 문서는 관리자 센터 개선 1~4단계를 독립된 Git 기준점으로 저장하고, 나중에 단계 간 변경점을 비교하기 위한 작업 기록이다.

## 진행 원칙

- 각 번호는 개별 체크포인트 브랜치와 기준 커밋 SHA로 저장한다.
- 다음 번호 작업은 직전 번호의 체크포인트를 기준으로 이어간다.
- 기존 직원용 화면·기능은 유지한다. 해당 단계 범위에 없는 직원용 동작은 변경하지 않는다.
- 현재 업체 대표 계정 1개 관리 구조를 유지한다. 복수 관리자, 대표/일반 관리자 구분, 관리자 추가 구매는 구현하지 않는다.
- 직원 개인 배송기록, 개인 계정 설정, 로그인 정보는 회사 관리자 데이터 백업 범위에 넣지 않는다.
- Supabase 운영 DB 마이그레이션 적용과 PR 병합은 별도 승인 전까지 하지 않는다.

## 단계별 결과

| 번호 | 작업 | 구현 결과 | 검증 상태 |
|---|---|---|---|
| 1 | 관리자 데이터 백업·복구 | 자동 변경 이력, 수동 백업, 백업 목록·상세 조회, 현재/백업 비교, 복구 직전 자동 보관, 업체 대표 권한 검사 | 1단계 커밋에서 테스트와 Android APK 빌드 성공 |
| 2 | 주간 근무표 편의 | 팀별 템플릿 저장/불러오기/삭제, 지난주 복사, 임시 근무표 미리보기, 초안 서버 저장, 버전별 변경 이력 및 복구 | 최종 통합본에서 React·Android 빌드 성공 |
| 3 | 휴무 요청·승인 이력 | 기존 직원 간 휴무 교환 및 추가 휴무 승인 로직 유지, 관리자 화면에서 추가휴무 대기 목록과 교환/추가휴무 처리 이력 조회 | 최종 통합본에서 React·Android 빌드 성공 |
| 4 | 부족량·자동 배치 검증 개선 | 수동 휴무 변경 시 자동 생성과 같은 백업 자격·이력 점수로 재배치, 격주 근무·백업 중복·휴무 백업 배정 충돌·미배정 경고, 확정 직전 재검증 | 일정 엔진 테스트와 최종 Android APK 빌드 성공 |

## 배포 상태 및 미완료 항목

- PR #24는 feature/shared-company-admin-data에서 feature/account-data-isolation으로 열린 Draft PR 상태이며 아직 병합하지 않았다.
- 신규 마이그레이션은 저장소에 추가되어 있으나 Supabase 운영 DB에는 적용하지 않았다.
- 따라서 실제 운영 앱에서 백업·템플릿·이력·자동 재배치 기능이 활성화됐다고 간주하지 않는다.
- 운영 반영 전에는 마이그레이션 순서, 권한, RLS/RPC, 실제 조직 데이터에 대한 검증이 별도로 필요하다.

## 변경 범위

- 백업 대상: 회사 공용 지역·팀·직원·노선.
- 근무표 이력 대상: 팀별 주간 schedule, 직원 상세, 경고, 임시/확정 상태.
- 휴무 이력 대상: 직원 간 휴무 교환 및 추가 휴무 요청의 처리 결과.
- 개인 배송기록 및 개인 설정: 제외.
- 관리자 권한: 현행 대표 계정 1개 구조 유지.
