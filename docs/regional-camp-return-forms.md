# 타지역 반품 채번 Google Forms 등록

## 이번 변경 범위

- 기존 청주 기본 양식 URL과 entry 번호는 변경하지 않습니다.
- 로그인 사용자는 공개 Google Forms 링크만 입력해 본인 캠프 양식을 등록할 수 있습니다.
- 서버는 양식 제목의 '반품' 바로 앞에 있는 캠프명을 우선 추출합니다. 예: `청주1캠프 반품 송장 발행 / 채번 요청` → `청주1캠프`. 제목에 명확한 캠프명이 없을 때만 '요청 캠프' 선택지를 보조 기준으로 사용합니다.
- 양식 소속 캠프명과 실제 요청 가능한 캠프 선택지는 서로 다른 정보로 취급합니다. 제목에서 추출한 캠프명과 드롭다운 선택지가 달라도 제목의 캠프명을 유지하고, 선택지는 요청 화면의 드롭다운에 그대로 제공합니다.
- 필수 entry 연결과 캠프명이 모두 명확하면 분석 직후 자동으로 저장합니다.
- 일반 이용자 화면에는 기술적인 entry 번호와 전체 분석 목록을 기본 노출하지 않습니다. 등록된 캠프 카드를 누르면 연결 정보와 원본 링크를 펼쳐 보여줍니다.
- 자동 연결이 불확실한 경우에만 누락된 항목을 직접 확인하는 화면을 표시합니다.
- 서버 함수가 Google Forms 공개 페이지에서 문항명, entry 번호, 필수 여부, 선택값을 추출합니다.
- 운송장번호, 기사님 아이디, 채번 수량을 자동으로 연결하고, 캠프 문항이 필수이면 캠프 항목도 반드시 연결하도록 합니다. 캠프 선택값은 등록 시 기본값으로만 지정할 수 있으며, 실제 채번 요청 화면에서는 해당 양식의 선택지 전체를 사용합니다.
- 자동 분석이 모호하거나 실패하면 사용자가 문항을 직접 연결할 수 있습니다.
- 링크 분석 성공, 수동 연결 필요, 분석 실패 내역을 운영자 접수함에 저장합니다.
- 운영자는 기존 채번 화면의 '타지역 캠프 양식 등록 / 관리'에서 '전체 캠프 링크 접수 내역'을 확인합니다.

## 배포 순서

1. 작업 브랜치의 최신 코드를 받습니다.

   ```bash
   git pull --ff-only origin feature/regional-camp-return-forms
   ```

2. 이번 변경은 사용자별 마지막 모바일 캠프 선택값을 저장하기 위해
   `supabase/migrations/20261115_camp_return_default_mobile_camp.sql`을 추가합니다.
   **이 파일의 전체 SQL만 Supabase Dashboard > SQL Editor에서 실행**하고 성공 결과를 확인합니다.
   그다음 Mac 터미널에서 연결된 운영 프로젝트의 마이그레이션 이력만 기록합니다.

   ```bash
   supabase migration repair 20261115 --status applied --remote
   ```

   기존 운영 Supabase 프로젝트에는 `20261113`, `20261114`가 이미 적용되어 있습니다.
   운영 DB에서 `supabase db push`를 실행하지 마세요. 이전 날짜의 미적용 마이그레이션도
   이번 작업과 무관하므로 밀어 넣지 않습니다. 다른 환경에 적용할 때도 기존 스키마와
   마이그레이션 이력을 먼저 확인하고 필요한 SQL만 별도로 적용합니다.

3. 분석 Edge Function을 대상 프로젝트에 배포합니다.

   ```bash
   supabase functions deploy analyze-camp-return-form --remote=<PROJECT_REF>
   ```

   Supabase의 기본 환경변수 `SUPABASE_URL`, `SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY`를 사용합니다. 이 키를 앱의 프론트엔드 코드에 넣으면 안 됩니다.

4. 앱을 빌드하고 Android 프로젝트에 반영합니다.

   ```bash
   npm run build
   npx cap sync android
   ```

## 앱 사용 방법

1. 앱에 로그인합니다.
2. 더보기 > 반품 채번 요청으로 이동합니다.
3. '반품 채번 요청' 제목 오른쪽의 '양식 등록/관리' 버튼을 누릅니다. 등록 관리는 채번 정보 입력 및 '설문지 자동 입력'과 분리된 메뉴입니다.
4. 공개 Google Forms 보기 링크만 입력하고 '캠프 양식 자동 등록'을 누릅니다.
5. 서버가 양식 제목과 캠프 선택지를 이용해 캠프명과 입력 항목을 분석합니다.
6. 자동 연결이 완전하면 별도 저장 조작 없이 등록됩니다. 자동 확인이 어려운 문항이 있을 때만 필요한 항목을 수동으로 연결합니다.
7. '등록된 캠프' 목록에서 캠프 카드를 누르면 연결 정보와 원본 양식 링크를 확인할 수 있습니다.
8. 신규 사용자는 처음에 채번 양식이 미선택 상태이며, 상단 안내에 따라 캠프 양식을 등록하거나 '청주 기본 양식'을 직접 선택합니다. 청주 기본 양식은 삭제하지 않고 필요할 때 선택할 수 있도록 유지합니다.
9. 양식을 등록하면 해당 캠프 양식이 채번 화면의 기본 선택으로 자동 저장됩니다. 이후 다른 양식을 선택해 채번 요청을 열면 마지막으로 사용한 양식이 계정별 기본 선택으로 저장되어 다음 진입 때도 유지됩니다. 기존 사용자는 저장된 선택을 유지하며, 과거에 사용하던 청주 양식도 계속 선택 상태로 복원됩니다.

## 현재 분석 대상 및 제한

- 현재는 공개된 Google Forms의 `/viewform` 공유 링크와 `/formResponse` 응답 링크를 모두 입력받습니다. `/formResponse`는 같은 양식 ID의 `/viewform` 주소로 자동 변환한 뒤 분석합니다.
- 앱에 내장된 청주 기본 양식의 ID를 다시 등록하려고 하면 중복 등록을 막고, 채번 화면에서 기존 `청주 기본 양식`을 선택하도록 안내합니다.
- `forms.gle` 단축 링크, 로그인/권한이 필요한 비공개 양식, Google Forms 이외의 폼은 지원하지 않습니다.
- 문항명이 모호하거나 같은 역할의 항목이 여러 개면 자동 연결하지 않고 직접 확인하도록 합니다.
- 양식 선택 후 '요청 모바일 캠프'는 해당 Google Forms 문항의 선택지가 2개 이상이면 드롭다운으로 표시하고, 1개이면 하나의 고정값으로 표시합니다. 여러 선택지 중 사용자가 선택한 값이 해당 entry ID로 미리 입력됩니다. 청주 기본 양식도 동일한 규칙을 사용합니다.
- 로그인 사용자가 지역 양식에서 선택한 모바일 캠프 값은 드롭다운을 바꾸는 즉시 `camp_return_profiles.default_mobile_camp`에 저장합니다. 다음 접속 시 마지막으로 사용한 양식과 선택값을 함께 복원합니다. 선택지가 하나뿐인 양식은 해당 고정값을 양식 선택 시 저장합니다.
- HTML 문항 구조가 바뀌면 자동 분석이 실패할 수 있습니다. 이 경우 운영자 접수함에 링크와 오류 메시지가 저장됩니다.
- 양식 제출은 기존 동작과 동일하게 Google Forms가 열린 뒤 사용자가 내용을 확인하고 직접 제출합니다. 앱이 Google Forms의 최종 제출 성공이나 송장 발급 결과를 확인하지는 않습니다.
- 운영자 접수함은 최근 100건을 표시합니다. 접수 기록에는 링크, 캠프명, 등록자 이메일, 양식 제목, 분석된 문항/entry 번호, 분석 상태와 오류가 저장되며 Google Forms 원본 HTML은 저장하지 않습니다.
