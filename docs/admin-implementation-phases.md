# 관리자 기능 단계별 개발 기록

이 문서는 관리자 기능 개선을 4개 독립 단계로 나누어 각 단계의 기준 브랜치와 검증 상태를 보존하기 위한 기록이다.
각 단계는 이전 단계 브랜치에서 분기하며, 다음 단계 작업을 시작해도 완료된 단계의 브랜치와 PR은 수정하지 않는다.

## 단계별 체크포인트

| 번호 | 작업 | 기준 브랜치 | 작업 브랜치 | 상태 |
|---|---|---|---|---|
| 1 | 관리자 데이터 백업 및 복구 | `feature/shared-company-admin-data` | `feature/admin-data-backup-restore` | 구현 중 |
| 2 | 주간 근무표 템플릿·지난주 복사·변경 이력 | 1단계 완료 브랜치 | `feature/schedule-workflow-tools` | 대기 |
| 3 | 직원 휴무 교환·추가 휴무 요청 및 승인 흐름 | 2단계 완료 브랜치 | `feature/dayoff-request-approval` | 대기 |
| 4 | 부족량 분석·노선 배치·자동 생성 검증 | 3단계 완료 브랜치 | `feature/shortage-auto-assignment` | 대기 |

## 1단계 범위

- 회사 공용 운영 데이터(지역·팀·직원·노선)를 변경 전 자동 백업
- 대표가 원하는 시점에 수동 백업 생성
- 최근 자동 백업과 수동 백업 이력 조회 및 내용 미리보기
- 선택한 백업 복구 전에 현재 상태도 별도 보관
- 버전 충돌 검사와 회사 소유자 검증 유지
- 자동 백업은 회사별 최근 100건을 보관하고, 수동 백업은 자동 정리 대상에서 제외
- 직원 개인 장부, 개인 설정, 로그인 및 기존 직원용 화면은 변경하지 않음

## 단계 완료 시 기록할 항목

- PR 링크 및 최종 커밋 SHA
- 변경 파일 목록
- 자동화 테스트·빌드·Android 빌드 결과
- Supabase 마이그레이션 적용 여부
- 기준 브랜치 대비 변경 파일 및 주요 동작 차이

## 주의

- `feature/shared-company-admin-data`의 기존 동기화 작업은 선행 단계다. 1단계 마이그레이션은 그 테이블과 RPC가 먼저 적용되는 것을 전제로 한다.
- 운영 Supabase DB에 마이그레이션을 직접 적용하지 않는다. 코드 검토, 테스트 및 별도 배포 확인 후에만 적용한다.
- 여러 관리자 계정, 관리자 등급 구분, 관리자 추가 구매는 이번 1~4단계 범위가 아니다.
